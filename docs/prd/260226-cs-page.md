## Context

- MergeProject는 현재 게임 개발팀 내부 검증용 플레이그라운드로 사용 중이며, P32·P40 게임 프로토타입, 스트링 체크 도구 등이 운영 중.
- 게임 서비스 런칭을 대비해 **고객지원(CS) 페이지**를 내부에서 먼저 검증·완성한 후, 추후 외부 도메인으로 이전 예정.
- 내부 이전 시 기존 서비스와 동일한 Supabase 인스턴스와 인증 게이트(Supabase Auth)를 그대로 활용.
- 현재 MergeProject에는 CS 페이지가 전혀 없으며, 문의 접수 채널도 부재한 상황.
- **이전 예정**이라는 제약 조건으로 인해 CS 페이지는 `/cs/*` 경로에서 독립적인 레이아웃(자체 헤더·푸터)으로 설계하고, 전역 AppShell의 글로벌 footer는 표시하지 않음.
- 추후 CS 어드민 대시보드(문의 목록 조회·상태 관리) 확장 가능성을 고려하여 `cs_submissions` 테이블 스키마는 확장 친화적으로 설계.
- 검색은 서버 비용 없이 정적 콘텐츠 클라이언트 사이드 키워드 검색으로 구현. 아티클은 더미 데이터로 시작.
- 문의(Contact Us) 폼은 Supabase `cs_submissions` 테이블에 저장.
- 기술 스택: Next.js 16, React 19, TypeScript, Tailwind CSS v3, Supabase SSR, next-themes (다크모드).

## Goals / Non-Goals

**Goals (목표):**
- `/cs` 메인 페이지: 히어로 헤더, 키워드 검색바, 6개 카테고리 그리드, What's New 섹션 구현
- `/cs/[category]`: 6개 카테고리별 아티클 목록 페이지 (카테고리당 더미 아티클 5개)
- `/cs/search?q=...`: 30개 더미 아티클 대상 클라이언트 사이드 키워드 검색 결과 표시
- `/cs/contact`: Contact Us 폼 → Supabase `cs_submissions` 테이블 저장
- `/cs/refund-guides`: 환불 정책 정적 Q&A 페이지
- 독립 레이아웃: CsHeader + CsFooter (기존 글로벌 footer 제거), AppShell 분기 처리
- 기존 Navbar에 CS 링크 추가
- 다크모드: 기존 프로젝트와 동일하게 Tailwind `dark:` 클래스로 지원

**Non-Goals (비목표):**
- CS 어드민 대시보드 (문의 목록 조회·상태 관리) — 이번 범위 아님
- 다국어(i18n) 실제 locale 전환 — LanguageModal은 더미 UI
- 파일 첨부 실제 업로드 — 파일명만 저장 (Supabase Storage 연동 없음)
- 실시간 채팅 상담 — Contact 폼 비동기 접수만
- 알림 이메일 발송 — 이번 범위 아님
- SEO 최적화 — 외부 이전 후 별도 처리
- CookieModal·AccessibilityDrawer 실제 기능 — 더미 UI

## Success Definition

**정량적:**
- `/cs`, `/cs/[category]`, `/cs/search`, `/cs/contact`, `/cs/refund-guides` 5개 라우트 정상 렌더링
- Contact Us 폼 submit 시 Supabase `cs_submissions` 테이블에 레코드 삽입 성공
- 검색어 입력 → `/cs/search?q=...` 이동 및 30개 더미 아티클 중 키워드 매칭 결과 표시
- 빌드(`next build`) 에러 없음

**정성적:**
- 실제 게임사 CS 사이트와 유사한 UX (카테고리 그리드, What's New 섹션, 헤더 히어로)
- CS 페이지 내에서 글로벌 footer 미표시 → 독립 레이아웃 분리가 AppShell 레벨에서 확인
- 기존 Navbar에서 CS 링크로 접근 가능
- 폼 유효성 검증 (이메일 일치 확인, 필수 필드)이 직관적으로 작동
- 내부 팀원이 실제로 폼 제출 → Supabase 대시보드에서 레코드 확인 시 데이터 정합성 이상 없음
- 다크모드 전환 시 CS 페이지 전체 UI가 기존 프로젝트와 일관된 스타일로 표시

## UX Acceptance Criteria

**메인 페이지 (`/cs`)**
- 페이지 진입 시 CsHeader 히어로 영역, 검색바, 6개 카테고리 카드, What's New 6개 카드가 모두 표시된다
- 검색바에 텍스트 입력 후 Enter 또는 검색 버튼 클릭 시 `/cs/search?q={query}`로 이동한다
- 빈 쿼리로 검색 시 이동하지 않는다 (버튼 비활성 또는 무시)
- "문의 메일 보내기" 버튼 클릭 시 `/cs/contact`로 이동한다
- 카테고리 카드 클릭 시 `/cs/{category-slug}`로 이동한다
- 글로벌 footer가 표시되지 않고, CsFooter가 페이지 하단에 표시된다

**카테고리 페이지 (`/cs/[category]`)**
- 유효한 슬러그 진입 시 해당 카테고리명과 소속 아티클 5개가 표시된다
- 존재하지 않는 슬러그 진입 시 Next.js 404 페이지로 이동한다

**검색 페이지 (`/cs/search`)**
- URL의 `?q=` 값이 검색바에 미리 채워진 상태로 표시된다
- 매칭 결과 존재 시 아티클 목록을 우선순위(title > body > tag) 순으로 표시한다
- 결과 없을 시 "No results for '…'" empty state 메시지를 표시한다

**Contact Us (`/cs/contact`)**
- 모든 필수 필드(날짜·토픽·설명·이름·이메일·이메일 확인)가 비어 있으면 Submit 버튼이 비활성화된다
- emailConfirm 필드에서 포커스 아웃(blur) 시 이메일 불일치 → 필드 하단에 빨간 에러 메시지 표시
- 이메일 일치 + 모든 필드 입력 완료 시 Submit 버튼이 활성화된다
- 이메일 필드 변경 시 실시간으로 일치 여부를 재검증하여 Submit 버튼 활성/비활성 상태가 즉시 반영된다
- Submit 클릭 후 API 응답 대기 중 버튼에 로딩 상태가 표시된다
- 제출 성공 시 폼이 Thank you 메시지로 교체된다
- "Documentation required for refund" 링크 클릭 시 `/cs/refund-guides`로 이동한다

## User Flows

```mermaid
flowchart TD
    A([사용자 진입 /cs]) --> B{탐색 방식}

    B -->|검색바 입력| C[/cs/search?q=...]
    C --> D{검색 결과}
    D -->|결과 있음| E[아티클 목록 표시]
    D -->|결과 없음| F[Empty state 표시]

    B -->|카테고리 카드 클릭| G{슬러그 유효?}
    G -->|유효| H[/cs/category - 아티클 목록]
    G -->|무효| I[404 페이지]

    B -->|문의하기 버튼| J[/cs/contact]
    J --> K[폼 입력]
    K --> L{유효성 검증}
    L -->|이메일 불일치| M[빨간 에러 표시]
    M --> K
    L -->|모든 필드 완료| N[Submit 활성화]
    N --> O[POST /api/cs/submit]
    O --> P{응답}
    P -->|성공| Q[Thank you 메시지]
    P -->|실패| R[에러 메시지 표시]

    B -->|What's New 카드| S[더미 콘텐츠]
```
